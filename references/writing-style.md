# 写作规范

抽取自 `ai-paper-reader`，用于约束 arxiv-paper-notes 产出的笔记风格。

## 目标

笔记可直接发布到技术社区（知乎、掘金、公众号）：

- 内容完整：核心技术细节不遗漏
- 专业易读：先给直觉，再给细节
- 客观准确：基于论文内容，推测内容必须标注「推测」
- 有深度：分析设计选择背后的原因，对比相关工作，指出适用范围和局限

## 应该做

1. 术语规范，公式和符号与论文原文严格一致
2. 复杂概念先直觉后细节，可用类比
3. 公式逐项解释变量含义，长公式分步解释
4. 层次分明，最多三级标题嵌套
5. 关键数字给出具体值（如「Recall@10 提升 12.4%」），不写「显著提升」

## 必须避免

1. AI 套话和模板句式，以下词句一律不用：
   - 「本文的核心贡献是」「该方法的优势在于」「综上所述」「值得注意的是」
   - 「具有重要意义」「广泛应用前景」「为该领域提供了新思路」「这是一篇重要的工作」
   - 「不难发现」「众所周知」「总而言之」
2. 不带具体分析的泛泛评价
3. 过度格式装饰：不用 emoji，不整句加粗，不过度嵌套列表
4. 第一人称：不写「我认为」「我的理解是」

## 公式

- 行内用 `$...$`，独立公式用 `$$...$$`，`$$` 独占一行
- 保留原文编号，写成 `$$ ... \tag{3} $$`
- 论文自定义宏（`\newcommand`）必须展开成标准 LaTeX，确保 GitHub / Obsidian / 知乎可渲染
- 公式之后紧跟「其中：」逐项列出变量及含义，再写一段「直觉」或「为什么这样设计」

## 图表

```markdown
![Figure 1: 整体架构](images/<arxiv_id>/fig1_arch_overall.png)

> 原图注：<caption 中文翻译>

**关键信息**：
- ...

**对应正文**：第 3.2 节
```

图片命名：`fig{序号}_{类型}_{简述}.png`，类型取 `arch` / `method` / `result` / `ablation` / `compare` / `other`。

表格：关键表格（主结果、消融）完整转写成 Markdown 表格，保留原表加粗的最优值，表下用 1-3 句话提炼结论。

## 深度理解问答

问题类型：

1. 原理理解：为什么这样设计，与替代方案相比如何
2. 细节辨析：符号或操作的具体含义，易混淆概念
3. 边界条件：什么情况下会失效，前提假设是什么
4. 延伸思考：能否迁移到其他场景，可能的改进方向

答案要求：直接展示不折叠；有论证不是断言；适当举例；论文未说明的部分标注「推测」。

## 难度等级

- ⭐ 入门级：无需专业背景
- ⭐⭐ 基础级：了解深度学习基础
- ⭐⭐⭐ 进阶级：熟悉相关领域
- ⭐⭐⭐⭐ 专业级：需要较深的领域知识
- ⭐⭐⭐⭐⭐ 专家级：涉及复杂数学或前沿研究
